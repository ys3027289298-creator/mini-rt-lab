# scramble

对采样序列做逐像素 / 逐帧随机化，消除复用同一序列导致的空间规则花纹，
同时保证逐帧可复现。

`make test` 跑自检；`make bench` 输出相关性 / 伪影指标表；
`make dump` 导出误差图（PGM）。

## 问题

同一序列在每个像素、每一帧都复用（"reuse"）时，误差是确定的：
相邻像素的误差完全相关（corr = 1.000），逐帧也完全相关（corr = 1.000），
所以多帧平均**不会**把它压下去，误差图上就是固定花纹。

## 做法

基础点集是 16 点的 (0,4,2)-net（每 4×4 单元、每行/列条带各恰有一点），
随机化有三种可组合的方式：

| 标志 | 含义 |
|---|---|
| `SC_FRAME` | 帧号参与密钥推导 |
| `SC_PIXEL` | 像素坐标参与密钥推导 |
| `SC_ROT` | Cranley–Patterson 旋转：整组样本加同一随机偏移（mod 1） |
| `SC_PERM` | Owen 嵌套数字置换：对样本索引的二进制位做双射置换，严格保持分层 |

密钥由 `(seed, frame?, pixel?, 维度, 核)` 经整数哈希得到，**没有任何浮点随机数**：
同一组输入在任意运行、任意机器（已验证 -O0/-O2/-O3、-march=native）产出逐位相同的序列。

注意：旋转用的是 [0,1) 内的连续偏移，会轻微破坏 net 的严格分层（这是已知取舍）；
需要每帧严格分层时只用 `SC_PERM`。两者都加就是常规的 "scrambled net"。

## 指标

`make bench` 渲染一个解析场景（3.3 像素棋盘 + 缓慢明暗渐变），
参考图是**解析像素平均**（按 cell 逐块积分，不是超采样求积，
否则参考值本身的数值误差会给所有指标设一个下界）。分别统计：

- `seq corr neighbor`：相邻像素样本序列（按样本下标配对）的相关系数
- `seq corr frame 0-1`：同一像素第 0/1 帧序列的相关系数
- `err corr first-last`：首末帧误差图的相关系数（≈1 表示花纹不随帧变化）
- `persistence = rmse/mean ÷ rmse/frame`：1 表示多帧平均完全无效
- `pattern px`：时间平均误差超过场景动态范围 1% 的像素数
- `pattern blk`：其中误差同样超阈的 4×4 块数（块平均抹掉了逐像素噪声，
  剩下的就是可见的空间结构；这是"花纹像素数"的主指标）

seed=20261122, 16 帧：

| mode | seq corr neighbor | seq corr frame 0-1 | err corr first-last | rmse/frame | rmse/mean | persistence | pattern px | pattern blk | pattern % |
|---|---|---|---|---|---|---|---|---|---|
| reuse | +1.000 | +1.000 | +1.000 | 0.01126 | 0.01126 | 1.000 | 5736 | 208 | 1.08% |
| frame_rot | +1.000 | −0.200 | −0.187 | 0.01499 | 0.00472 | 0.315 | 1784 | 0 | 0.00% |
| frame_perm | +1.000 | +0.072 | +0.354 | 0.01218 | 0.00764 | 0.627 | 5440 | 64 | 0.33% |
| frame_both | +1.000 | +0.236 | −0.494 | 0.01623 | 0.00429 | 0.264 | 1639 | 0 | 0.00% |
| pixel_rot | −0.016 | +1.000 | +1.000 | 0.01509 | 0.01509 | 1.000 | 6236 | 992 | 5.17% |
| pixel_perm | +0.044 | +1.000 | +1.000 | 0.01193 | 0.01193 | 1.000 | 5809 | 448 | 2.33% |
| pixel_both | −0.001 | +1.000 | +1.000 | 0.01626 | 0.01626 | 1.000 | 6273 | 1184 | 6.17% |
| full | +0.004 | −0.004 | −0.003 | 0.01638 | 0.00414 | 0.253 | 1218 | 0 | 0.00% |

要点：

- 只加帧随机化（`frame_*`）：花纹随帧变化，`persistence` 降到 0.26–0.63，
  但**单帧内**相邻像素仍完全相关（corr = 1.000），单帧仍能看到花纹。
- 只加像素随机化（`pixel_*`）：空间相关消失（corr ≈ 0），但每帧相同，
  `persistence` = 1.000，多帧平均无效。
- 两者都加（`full`）：空间去相关 + 逐帧可平均，花纹块归零（208 → 0）。

`reuse` 的 pattern 不随帧数变化，`full` 按 1/√F 衰减：

| mode | frames | rmse/mean | persistence | pattern px | pattern blk |
|---|---|---|---|---|---|
| reuse | 1 | 0.01126 | 1.000 | 5736 | 208 |
| reuse | 16 | 0.01126 | 1.000 | 5736 | 208 |
| reuse | 64 | 0.01126 | 1.000 | 5736 | 208 |
| full | 1 | 0.01632 | 1.000 | 6323 | 1248 |
| full | 4 | 0.00811 | 0.497 | 3303 | 16 |
| full | 16 | 0.00414 | 0.253 | 1218 | 0 |
| full | 64 | 0.00205 | 0.125 | 296 | 0 |

`persistence` 是比块计数更稳健的收敛证据：块数在阈值附近会抖动，
`full` 的 1.000 → 0.497 → 0.253 → 0.125 正好是独立帧平均的 1/√F。

## 可复现

```
$ ./scramble checksum 42
checksum=d65062c7604ae784
```

同一 seed 重复运行结果相同；`golden_seed42` 自检把这个摘要钉在测试里，
改动生成器会直接失败。`./scramble bench 20261122 16` 连跑两次逐字节一致，
与编译优化等级无关。

## 用法

```
./scramble                       # 自检
./scramble bench [seed] [frames] # 指标表
./scramble checksum [seed]       # 单一摘要
./scramble dump [seed] [frames]  # err_reuse.pgm / err_full.pgm
```
