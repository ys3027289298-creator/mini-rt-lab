# bvh / material mutation test report

Generated by `tools/report.py` from `results/results.json`.  Do not edit by hand.

## 1. What this measures

A defect is injected into `bvh/src/bvh.c` or `material/src/material.c`, the
patched source is compiled **unmodified** into a small path tracer
(`render/rt.c` calls the real module through `render/*_shim.c`, which
`#include` the module source), and the resulting frames are compared with
frames from the pristine sources.

A defect counts as **caught** when at least one scene shows a visible change:

- at least `8` pixels differ by at least `3` in some RGB channel (8-bit).

The comparison is **paired**: mutant and reference share camera, resolution,
sample count, seed, and RNG stream, so Monte-Carlo noise cancels.  That was
measured, not assumed -- see section 5.

Neither the scene list nor the threshold was tuned per mutant.  Every mutant
is scored by the same rule on all scenes.

Configuration: 320x240, 16 spp, seed 1, scenes: grid, rough, occlude, grazing, warm.
Compiler: `gcc (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0`.

The `tree == brute` check is load-bearing: the tree build permutes the
primitive array, and overlapping boxes can be hit at exactly the same
`t`.  The shim resolves such ties by lower primitive id, so tree-shape
changes are provably invisible instead of randomly visible.

`tools/sensitivity.py` scales the Lambert `1/pi` factor by a relative error
and finds the smallest error that the 8-bit comparison can see.

|---|---:|---|
| 0.01% | 0 | False |
| 0.03% | 0 | False |
| 0.10% | 0 | False |
| 0.20% | 0 | False |
| 0.30% | 0 | False |
| 0.50% | 0 | False |
| 1.00% | 0 | False |

Smallest error visible in at least one scene: **2.00%**; in every scene:

defects smaller than roughly 2% of the affected term are not observable

## 6. Threats to validity

- **Single renderer, five scenes.**  A defect that only shows at a different
  camera, a different light, or higher bounce depth would be missed.  An
  ablation run limited to `grid,rough,occlude` still caught every visible
  defect at the final settings, so the last two scenes are not load-bearing
  for this catalogue; they add margin (see detection margins above) and
  coverage of cases this catalogue happens not to contain.
- **Paired-only comparison.**  Bitwise-stable rendering is a property of
  this build and these sources; it was verified (section 5), not assumed.
- **Equivalent mutants are hand-classified** (section 4 lists the argument
  for each).  A wrong classification would corrupt the false-positive rate.
- **Sub-threshold defects are expected misses**, quantified in section 5.
  They are excluded from the headline rate.

## 7. Reproduce everything

```sh
cd mut
python3 -I tools/mutate.py --check            # every patch anchor matches once
python3 -I tools/validate.py                  # oracle sanity, writes results/validate.json
python3 -I tools/run_mutations.py --out results
python3 -I tools/sensitivity.py               # writes results/sensitivity.json
python3 -I tools/report.py                    # writes REPORT.md
```

No third-party libraries: the harness is Python stdlib plus `gcc`; images are
written as raw RGB with a Python `zlib` PNG encoder.
