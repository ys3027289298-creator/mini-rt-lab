# bvh

`make test` 跑自检。`bvh` 是建树/单盒求交基础模块，`packet` 是按方向分组的
光线包遍历与标量逐条遍历的对照实现（`src/packet.c`）。

## 方向分组

每条光线按方向进一个桶：先选主导轴的 6 个朝向面（±x/±y/±z），再在两个
横向轴上按斜率 `d_t/d_major` 各分 `NBUCKETS=4` 格，共 96 个桶。计数排序
把同桶光线连续摆放，每 `PACKET_K=8` 条切成一个包；桶内再按 pixel id 排序，
使包的组成与输入顺序无关。桶边界是方向斜率的确定性函数，同一光线无论以
什么顺序出现都进同一个包。

## 包遍历（`trace_packets`）

包带一个活动光线掩码走一遍 BVH，栈帧是 `(node, mask)`：

1. 节点包围盒只加载一次，包内共享（`node_fetches` 按包计数）。
2. 对活动光线算各自的 slab 区间，同时汇总包络
   `lo_i=maxmin t_enter,i`、`hi_i=minmax t_exit,i`。包络在某个轴向为空
   （`max(lo) > min(hi)`）时，**每条光线自己的精确谓词都必然为 miss**，
   整包跳过该子树，不做任何逐光线判定。
3. 包络不为空时，逐条光线执行与标量路径**完全相同的算术**
   （同一 `slab_intervals` + `slab_combine`，同样的 `tmax=ray->t`），
   miss 的光线从掩码剔除，命中的带着各自的私有 `tmax` 继续下行。
4. 叶子上只对掩码内光线做图元测试，最近命中状态（id 与 t）按光线私有。

### 为什么命中结果逐位一致

- 包络剔除只删"精确谓词一定为 miss"的测试，从不跳过任何一条会命中的
  （光线，节点）或（光线，图元）测试；
- 保留下来的测试走的是和标量遍历同一条代码路径、同样的浮点运算顺序，
  没有近似区间、没有共享 tmax，更新最近命中的顺序对同一条光线也完全
  一致（叶子内图元顺序由树结构固定）；
- 因此每条光线的命中 id 与 hit 距离的比特表示，与 `trace_scalar` 完全
  相同，与它被分到哪个包、输入顺序如何无关。
- 退化情形单独处理：平行光线（某 `|d_i|<1e-8`）不参与包络汇总，只走
  精确逐光线谓词，与标量路径的平行分支语义一致。

自检的 `*_exact_match` 同时比对命中 id 和 `t` 的原始浮点位
（`memcmp` 级，不是误差容限）。

## 顺序无关性

`results_equal` 按 pixel id 归位后逐位比对。自检覆盖：分组后随机打乱、
整体逆序、非相干射线打乱；由于桶内按 pixel id 规范化，不仅逐像素结果
一致，节点访问数等统计量在打乱前后也完全相同（`*_fetches_same`）。

## 实测数据（本机 `make test` 输出，128 图元场景）

相干针孔相机射线（256 条，相邻像素方向接近）：

| 指标/光线 | 标量逐条 | 方向分包 | 降幅 |
|---|---|---|---|
| 节点访问（包围盒加载） | 13.61 | 2.43 | **-82%** |
| 逐光线包围盒谓词 | 13.61 | 9.94 | -26% |
| 图元测试 | 2.23 | 2.23 | 0% |

非相干随机方向射线（256 条，对照组）：

| 指标/光线 | 标量逐条 | 方向分包 | 降幅 |
|---|---|---|---|
| 节点访问 | 3.66 | 1.79 | -51% |
| 逐光线包围盒谓词 | 3.66 | 2.27 | -38% |
| 图元测试 | 0.49 | 0.49 | 0% |

图元测试数两条路径严格相等（精确性的直接体现：分组只省节点流量，
不改变任何实际求交）。相干性越强，整包剔除越频繁，节点访问下降越多；
非相干场景仍有收益但明显变小，符合预期。

另外 `stress_20_scenes_bitexact` 在 20 个随机场景 × 随机射线（含零分量
方向、重复光线、碎片包）上验证逐位一致；ASan/UBSan、`-O0/-O2/-O3`、
gcc/clang 均通过。
