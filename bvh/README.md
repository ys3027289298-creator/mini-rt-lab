# bvh

中位数分裂 AABB 树、最近命中遍历、动画场景增量更新、重建判据与失效检测。

`make test` 跑自检。

## 增量更新：重算什么

叶子划分在 `build()` 时固定。一次 `refit(t, ids, nids)` 只重算被移动图元所在的**叶子及其全部祖先**：

```
脏集 = { leaf_of[id] : id in ids } ∪ { 这些叶子的祖先 }
```

正确性来自一个集合论证，而不是启发式：

- 树节点按子树划分图元。若某节点的子树不含任何被移动的图元，则其所有 `Prim::box` 都没变，由它们聚合出的 `Node::box` 仍有效。
- 脏集的定义恰好是「子树含脏图元」的全部节点。因此脏集之外的盒**必然**仍有效，可以原样保留。
- 脏集是祖先封闭的，所以按 `leaf → root` 由子写父即可；子节点已在本轮更新过。

实现用时间戳 `mark[]/stamp` 标脏，递归 `refit_fix()` 只在标记节点上走，返回实际重算的节点数。一次更新里重复 id、旧 id 都安全。`apply_tri()` 只改一个图元的顶点/盒/质心。

复杂度：`O(k · log n + k)`,其中 `k` 为脏叶子数；每帧重建是 `O(n log n)`。

自检 `test_refit_scope` 直接验证这两条：重算节点数**恰好等于**预期脏集大小（`refit_scope_exact`），且脏集外没有任何盒被改动（`refit_scope_isolated`）。

## 何时必须重建，而不是更新

判据由两条独立理由组成（`should_rebuild()` 返回位掩码）：

| 触发 | 判据 | 性质 |
|---|---|---|
| `REBUILD_TOPOLOGY` | `nprim != built_nprim` | **正确性必需** |
| `REBUILD_SAH` | `area_sum/root_area > 1.5 · q_build` | 仅影响性能 |

推导：

1. **图元集合不变时，refit 是精确的。** 每个叶子的盒按其当前图元重算，祖先盒由子盒取并。遍历的剔除只依赖「节点盒包含子树所有图元」，refit 逐帧重建了该不变量。所以此时无论运动多剧烈，命中结果都与重建树一致，**不需要**为了正确性重建。
2. **图元集合变化时，必须重建。** 叶子划分是旧图元集合的划分：新增图元的 `leaf_of` 无处可指，`refit` 只会重算既有区间，它永远进不了任何叶子；删除图元则留下悬空区间。`refit()` 对这类 id 无定义，因此这是唯一强制的重建。
3. **性能会漂移。** 中位数分裂是按建树时刻的分布切的。运动把几何搬到别的节点区间后，旧划分不再贴合，遍历的盒测试变多，但结果仍正确。用与尺度无关的 SAH 代理 `Σ(内部节点盒面积) / 根盒面积` 度量：refit 无法修复划分，重建可以，因此超过建树值的 `REBUILD_RATIO` 倍就重建。这是收益判据，不是正确性判据。

关键区别：**判据失效只会让遍历变慢，不会产生错误命中**（前提是第 1 条的精确性成立，即脏集与祖先链没写错）。错误剔除只可能来自更新实现本身出错，见下一节。

## 错误剔除的检出

两条互补的检查：

1. **不变量审计 `audit_contains()`** — 直接验证「每个节点盒包含其子树全部图元的盒」。任何陈旧叶子、漏掉的祖先都会立刻使某个内部节点不包含子盒，返回违规节点数。这是精确、低成本（`O(n)`）的检查，适合每帧跑一次。
2. **暴力对照 `ray_mismatch()`** — 同一光线分别走树和线性扫描，比较是否命中、图元 id、深度 `t`。它能抓到审计覆盖不到的情形：盒仍包含但数值上紧到浮点误差、或遍历栈处理错误。

`test_stale_detection` 注入两种典型的更新失效，并断言能检出：

| 注入的失效 | `audit_contains` | 暴力 vs 树 |
|---|---|---|
| 脏集漏掉被移动图元（完全不 refit） | 检出违规 | 暴力命中、树剔除（`stale_false_cull=1`） |
| 更新了叶子但漏掉祖先 | 检出违规 | 暴力命中、树剔除（`scope_false_cull=1`） |
| 正确 refit 后 | 无违规 | 一致（`stale/scope_repaired_hit=1`） |

`test_topology_change` 另外展示：新增图元后、重建前，树会漏掉它（`topo_wrong_before_rebuild=1`），`REBUILD_TOPOLOGY` 置位，重建后恢复一致。

## 结果一致性

三组动画测试都在**每一帧**把三种结果对齐：

`raycast(增量树)` vs `brute(同一增量树)` vs `raycast(每帧重建树)`

比较命中与否、图元 id、`t`（相对误差 1e-3）。所有测试中不一致数均为 0（`rigid_mismatch` / `partial_mismatch` / `scatter_mismatch`），且 `audit_contains` 每帧均无违规。射线瞄准图元当前质心，保证绝大多数射线真的命中，比较不是空的。

## 耗时

`gcc -O2`，WSL2，数字取多次运行的稳定区间。

| 场景 | 图元 | 每帧移动 | 每帧 refit 重算节点 | refit | 重建 | 加速 |
|---|---|---|---|---|---|---|
| 部分运动 | 4096 | 122 (3%) | ~700 / 5125 | ~25 µs | ~450 µs | **~18×** |
| 刚性平移（全部移动） | 1024 | 1024 (100%) | 全部 | ~33 µs | ~117 µs | ~3.5× |

解释：

- 全部图元都动时，脏集覆盖全树，refit 没有可跳过的节点；剩下的加速只来自免去排序/重排（重建的 `O(n log n)` 部分）。这是增量更新的下界，属于预期。
- 动画里通常只有少量图元动，此时 refit 成本与移动数成正比，加速随「移动比例」线性放大。
- 遍历质量不下降：`partial_box_tests_refit` 与 `partial_box_tests_rebuilt` 基本相同（~54 万次盒测试），因为 refit 树与重建树有相同的层次和盒。「省时间」来自少做构建工作，而不是查询变弱。

## 其它

- 空间分裂可能极不均衡（例如一个离群图元），会把递归深度拉成线性并撑爆遍历栈。`build()` 对任一子集小于 1/7 的分裂退回中位切分，`test_skewed_layout` 用「1000 个团簇 + 1 个 1e4 远处离群点」验证深度上界（实测深度 13）。
- `MAX_PRIM` 4096、`MAX_NODE` 8192、`MAX_STACK` 128；改容量时三者一起改。
- `make test` 之外，可用 `gcc -fsanitize=address,undefined` 构建，自检同样干净。
