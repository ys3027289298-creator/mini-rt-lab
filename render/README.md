# render

多线程软件光线追踪 + 时间一致性（temporal consistency）测试模块。

`make` 构建两个程序：

| 程序 | 作用 |
|---|---|
| `render` | 多线程整帧路径追踪，输出无损 float32 PFM |
| `compare` | 两个 PFM 逐像素、逐通道**位精确**比对 |

`make test` 运行一致性门禁脚本 `scripts/consistency_test.sh`。

## 用法

```sh
./render -w 64 -h 48 -s 16 -t 4 --seed 7 -o frame.pfm
# -w/-h 分辨率, -s 每像素样本数, -t 线程数, --seed 采样种子, -o 输出 PFM
./compare frame_a.pfm frame_b.pfm        # 退出码 0=完全一致, 1=有差异, 2=文件/用法错误
./compare --selftest                      # 比对器自检（负向用例）
```

PFM 为二进制 RGB float32、小端、行自底向上存储；compare 读取时翻转为
顶行优先（y=0 在顶部），报告坐标与渲染器扫描线索引一致。

## 确定性契约（如何消灭全局状态）

1. **无可变全局状态**：场景在 `main()` 构建一次，工作线程启动后只读；
   确定性路径上没有任何共享可变变量。
2. **每像素私有 RNG**：PCG32 实例位于 worker 栈上，由 `(x, y, seed)`
   经哈希播种。像素的随机数序列与由哪个线程、何时执行无关，不存在共享
   RNG 竞争或调度相关的抽取顺序。
3. **像素只写一次**：按行连续分带，每行恰好归属一个线程，无共享
   read-modify-write、无跨线程归约。线程数大于行数时自动收敛为按行分配。
4. **固定累加顺序**：样本严格按 `s = 0..spp-1` 顺序累加，浮点求和结果
   与线程调度无关。

因此同参数重复渲染、以及任意线程数（含不能整分行高的 3、7 等）下，
输出都应**字节级一致**。

## 不一致时的报告

compare 以位相等比较每个 float32 通道（不用容差），发现差异时输出首个
差异像素的坐标、通道及两侧的值（十进制 + 原始 hex），并统计差异通道数
与差异像素数：

```
DIFFERENT 64x48
first_diff: pixel=(12,7) channel=B
  a.pfm: 0.421875 (0x3ed80000)
  b.pfm: 0.421876 (0x3ed80001)
diff_channels=1 diff_pixels=1 (of 3072)
```

## 故障注入：`--rng=global`

确定性实现之外保留一个故意带 bug 的模式：全进程一把锁保护的共享 RNG，
种子取自时钟。此时抽取顺序依赖线程调度且每次运行种子不同，用于复现
“同一帧渲染两次结果不同”的全局状态问题，并验证测试脚本能抓到它。
真实渲染永远不要使用该模式。

## 测试覆盖（`make test`，15 项）

- **R1** 同参数两次独立渲染：compare 零差异 + `cmp` 字节级一致；
- **R2** 线程数 1/2/3/4/7/8/64（含不整分行高与超过行数的情况）全部与
  基线位一致，sha256 相同；
- **R3** compare 自检与人工构造的 PFM 差异均能正确报出首个差异像素的
  `(x, y, channel)`（含 PFM 底行翻转语义）；尺寸不匹配按错误处理；
- **R4** `--rng=global` 两次运行、以及不同线程数下均被检出不一致，
  证明门禁对全局状态类 bug 有效。

另已验证：`-O0..-O3` 输出 sha256 完全相同；ASan/UBSan 无告警；
奇数分辨率/线程数组合的压力渲染全部一致。
